56. CSS 是否存在父选择器？

历史：长期没有真正的父选择器，CSS 选择器只能"从父到子"向下选，不能"从子反查父"。
原因：浏览器匹配规则是从右向左，且文档流可能动态变化，子元素修改可能引发父级大量重算，性能开销大。
现状：CSS4 :has() 已被主流浏览器（Safari 15.4+/Chrome 105+/Firefox 121+）支持，可视为父选择器。

:has() —— 终于到来的父选择器

/* 选中含有 .active 子元素的 div */
div:has(> .active) { background: #ffe; }

/* 选中含有被勾选 input 的容器 */
label:has(input:checked) { ... }

没有 :has() 时的替代方案

  • JS 动态加父类名：parent.classList.add('has-active')
  • 把状态上提到父元素：.checked label
  • 用 :focus-within / :checked + 兄弟 等半父选择器

为什么历史上没有父选择器？

  • 匹配方向：CSS 引擎从右向左匹配，父选择需反向遍历，复杂度高
  • 动态文档：DOM 可随时增改，子→父影响范围大，重算成本高
  • 循环依赖：父状态可能影响子，子又反影响父，易死循环
  • :has() 实现也经过多年优化才落地
