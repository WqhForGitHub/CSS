40. CSS 工程化

CSS 工程化：用工程手段解决 CSS 在大型项目中的 组织、复用、维护、冲突、按需加载 问题。

核心问题

类名冲突（全局污染）→ 命名重复覆盖
样式复用 → 复制粘贴难以维护
文件拆分 → 模块化、按需加载
代码冗余 → Tree-shaking 移除未用样式
浏览器兼容 → 自动前缀/降级

① 模块化方案（解决命名冲突）

BEM 命名规范：block__element--modifier 
.card__title--active { }
.card__body { }
CSS Modules（编译期生成唯一类名） 
/* card.module.css */
.title { color: red; }
/* 编译后：.card_module__title__3fK */

import styles from './card.module.css';
<div className={styles.title} />
CSS-in-JS：styled-components / emotion，运行时生成唯一哈希类名 
const Box = styled.div\`color: red;\`;
<Box />

② 预处理后处理器

Sass/Less 写增强语法；PostCSS + autoprefixer 处理兼容/优化。

③ 工具链 / 框架

Tailwind（原子化 CSS，按需生成）、CSS Houdini（浏览器 API 扩展 CSS）、Critical CSS（首屏内联）。

④ 按需加载与 Tree-shaking

Webpack mini-css-extract-plugin 抽离 CSS、purgecss 移除未用 class，配合路由懒加载实现按页面拆包。

典型工程化链路

SCSS 源码 → Sass 编译 → PostCSS (autoprefixer+压缩) → Critical CSS 内联 → 整包打包拆分 → 上线 CDN
